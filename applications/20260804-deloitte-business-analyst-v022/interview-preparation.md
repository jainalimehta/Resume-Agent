## Explain GitHub Actions Accurately

GitHub Actions runs repeatable checks when repository changes are pushed. In Jainali's portfolio it supports SQL-project validation and consistency. It demonstrates exposure to automated checks and version-controlled workflows, but it is not evidence of production CI/CD, cloud deployment, infrastructure automation, or DevOps ownership.

## Explain the Project Workflow

1. Define the business questions and expected reporting outputs.
2. Design a relational schema and establish keys, relationships, constraints, and business rules.
3. Load and inspect data, then check completeness, validity, duplicates, and referential integrity.
4. Write SQL queries using joins, aggregations, CTEs, rankings, running totals, and window functions.
5. Validate outputs through repeatable scripts and GitHub Actions checks.
6. Interpret results, use Generative AI to support structured insight generation, and verify recommendations against SQL evidence.
7. Document KPI and Power BI dashboard plans; do not claim published interactive dashboards.

## Requirements and Solution-Design Approach

1. Identify stakeholders, business decisions, current workflow, pain points, constraints, and desired outcomes.
2. Separate business, functional, data, reporting, integration, security, and non-functional requirements.
3. Record assumptions, dependencies, priority, owner, acceptance criteria, and unresolved questions.
4. Validate understanding through workshops, walkthroughs, examples, and stakeholder review.
5. Maintain traceability from requirement to design, test case, issue, decision, and approval.
6. Communicate changes and risks clearly to both business and technical participants.

Present this as an approach supported by requirements and validation experience—not as ownership of enterprise software delivery.

- Defect severity versus priority; reproducible steps, expected result, actual result, evidence, owner, and status.
- Agile product backlog, user story, acceptance criteria, sprint planning, review, retrospective, and definition of done.
- Version control, pull requests, automated checks, release gates, monitoring, rollback, and lessons learned.
