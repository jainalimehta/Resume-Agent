## Technical Discussion Frameworks

### How do you approach an unclear data request?

1. Clarify the decision the stakeholder needs to make.
2. Define the population, timeframe, grain, dimensions, measures, and exclusions.
3. Confirm the source systems and known data limitations.
4. Write the requirement and expected output in plain language.
5. Build a small validated result before expanding it.
6. Reconcile figures to the source and review interpretation with the stakeholder.

### How do you validate a KPI?

- Write a precise business definition and identify inclusion/exclusion rules.
- Confirm grain and join cardinality so records are not duplicated.
- Test nulls, duplicates, valid ranges, totals, and edge cases.
- Reconcile aggregates to source data or a trusted baseline.
- Document the logic so another analyst can reproduce it.

### How would you work with messy data?

- Profile fields for missing values, inconsistent formats, duplicates, and invalid categories.
- Preserve raw data and separate cleaning logic from analysis logic.
- Standardize types and categories using explicit rules.
- Validate row counts and key totals after each transformation.
- Record assumptions and unresolved limitations before presenting conclusions.

### How do you simplify an insight for a senior leader?

Lead with the decision and the one most relevant finding, show only the supporting KPI or trend needed to establish it, explain the business implication, then state the recommended next action and any material caveat.
